# Economic.Express API

Private Django 5.2 / DRF backend for the adjacent Economic.Express Next.js frontend. Do not publish this repository. No remote is configured by this implementation.

## Developer setup

Requires Python 3.14 and PostgreSQL 17 or later. Create a virtual environment and install `requirements.txt`. Supply the variables documented in `.env.example` through your shell or deployment secret store; Django loads ignored `.env.local` and `.env` files generated by Neon; explicit process environment variables take precedence. Never commit these files.

```sh
python -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py check --deploy
```

`seed` creates Writer and Editor groups and optionally creates a superuser using `DJANGO_SUPERUSER_*`. It does not reset an existing user's password. Set `is_staff` for CMS users. Superusers are administrators. `seed --demo` imports 29 explicitly fictional/sample articles, 9 categories, authors, tags, videos and recent view counters. Existing articles are never overwritten. Demo timestamps are made recent, missing seed captions use the headline, and reading times are recalculated from the supplied bodies.

Run the web process with `gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 2 --threads 4` and a **separate persistent worker** with `python manage.py run_workers`. The worker retries webhooks and invalidates scheduled posts every two seconds; a sleeping web service alone cannot provide reliable scheduled publication. `run_workers --once` supports an external scheduler, with visibility delay determined by that scheduler's interval.

For local HTTP checks only, `SECURE_SSL_REDIRECT=False` disables the HTTPS redirect. Production defaults keep secure cookies, HTTPS redirects, HSTS, host checks and CSRF protection enabled. Only enable `TRUST_PROXY_PROTO=True` behind an ingress that strips client-supplied forwarding headers. IP throttles deliberately use `REMOTE_ADDR`; verify real-client-IP forwarding at the hosting ingress before launch. Do not blindly trust arbitrary `X-Forwarded-For` values.

## Storage and editor

Uploads use S3-compatible object storage (Cloudflare R2 supported), never local media. Set the AWS variables in `.env.example`, including a public HTTPS custom domain for image delivery. The frontend needs that domain in `IMAGE_STORAGE_HOST`. JPEG, PNG and WebP inputs are decoded, limited to 5 MB / 25 megapixels, stripped of metadata, resized within 1600×1600, and encoded as WebP quality 80. Inline image uploads require a staff session, article permission and CSRF token. TinyMCE assets are served locally with Django static files. Draft preview stays inside the authenticated CMS and is not the public frontend template.

## Contract

The handoff endpoints live under `/api/`. Videos are included in `home.videos[]` and also available at `/api/videos/`. Video `id` is the YouTube ID expected by the approved player. `home.lead` is null for an empty publication. The extra `/api/resolve/{article|category}/{slug}/` endpoint performs a single visibility query so Next can return an actual HTTP 404 before streaming. It is also used to stop archived cached articles from being served after an API-confirmed archive.

Ticker output retains `updated_at` from its actual source and adds `source` and `stale` diagnostics. Refreshes happen in the background, with ten-minute retry spacing. Gold/silver quotes use the USDINR conversion from the spec; intraday metal sparks use the latest available FX rate. Static fallback numbers are samples, not current market quotes. The frontend currently displays only the existing Delayed label; see the readiness report.

The webhook outbox is stored in PostgreSQL and delivery begins after commit. Failed deliveries back off and retry. Duplicate deliveries are harmless because tag invalidation is idempotent. Writers can edit only their own active drafts. Editors can publish and archive; restore returns an archived article to draft. Public querysets consistently exclude future, draft and archived articles.

## Verification

```sh
TESTING=True python manage.py test news
python manage.py makemigrations --check --dry-run
python manage.py check --deploy
pip-audit
```

Use a disposable PostgreSQL database and a role allowed to create a test database. `TESTING=True` disables background threads for isolated tests and permits SQLite for basic checks; PostgreSQL is otherwise mandatory. Never set `TESTING=True` on a deployed instance. `PRODUCTION-CHECK.md` records actual checks, evidence and launch blockers. This document is developer setup, not the deferred editorial operations guide.

## Neon demo connection

The backend is linked to project `curly-king-72601696`, branch `production`, in Singapore. `neon.ts` declares the existing public `article-images` bucket. Neon manages database/storage only; Django and Next.js still need web hosting for an externally accessible demo.

Run `neon deploy` from this backend folder to reconcile the services and pull credentials into `.env.local`. It provides `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`, and `AWS_REGION`. Set `AWS_STORAGE_BUCKET_NAME=article-images`. Django uses its existing psycopg driver, pooled connections with server-side cursors disabled, and S3 path-style/SigV4 storage. A custom image domain is optional for Neon; public object URLs use the branch endpoint and bucket path.

Use `DATABASE_URL_UNPOOLED` as the `DATABASE_URL` process variable for migrations. Do not print either connection URL into logs. Keep the pooled `DATABASE_URL` for normal API traffic. The frontend needs only the API URL and public storage hostname (`IMAGE_STORAGE_HOST`); database and storage keys remain in the backend.

Local `.env.local` files currently target HTTP ports 8001 (API) and 3001 (frontend), with `DEBUG=False` and an explicitly local `SECURE_SSL_REDIRECT=False`. Replace these settings with hosted HTTPS origins and enable the redirect when deploying. The demo editor credentials, if created by verification, are stored locally in ignored `.demo-login.json`.

## Temporary Render demo health check

The Docker image collects CMS static files during its build. At runtime it starts Gunicorn immediately; it does not perform schema migrations or seed content on each wake. Apply any future migrations once, with the Neon direct connection, before deploying a schema-dependent release. The database is already initialized for this demo.

`GET /health/` is a liveness endpoint that returns `{"ok": true}` without database queries. It deliberately does not check Neon or Yahoo. After Render is live, `sh scripts/configure-demo-scheduler.sh https://SERVICE.onrender.com` creates or updates the ten-minute HTTP job in the configured Google Cloud project and triggers a test execution. The script defaults to project `bcrm121`, location `asia-southeast1`; override `GCLOUD_PROJECT` / `SCHEDULER_REGION` as needed. Remove the job after the demo period. This reduces ordinary idle sleeps, not restarts or quota interruptions.
